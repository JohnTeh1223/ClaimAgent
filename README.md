# 浙江大学报销助手（批量复核版）

这是一个手动启动的 Windows 本地工具。程序读取 `01-待处理` 目录中的电子发票 PDF，先进行确定性校验和人工复核，只有在最终批次摘要页明确确认后，才会修改 WPS 表格和复制报销 PDF。

## 当前功能

1. 批量读取 `01-待处理` 中的全部 PDF（PyMuPDF 直接提取文本，不默认使用 OCR）。
2. 校验发票号码、日期、购买方、购买方税号、销售方、项目名称及金额关系。
3. 用 Windows GUI 展示复核队列和完整发票信息。
4. 写入前可编辑报销类别、统计表简称、型号/规格、单位、数量和报销月份。
5. 可排除某张发票，或将其标记并移入 `02-待复核`。
6. 最终显示整个批次的发票数、合计、分类汇总、目标文件名及会修改的表格。
7. 必须勾选明确同意框并点击“确认并执行批次写入”，才会开始任何正式写入。
8. 整批共用一次备份和回滚边界；任一步失败都会尝试恢复所有已修改表格、PDF 和源文件。
9. 成功后把源 PDF 移至 `03-已完成`，并写入 JSON Lines 处理日志。
10. 使用发票号码、批内冲突、历史成功日志、目标 PDF 和完成目录进行保守的重复检测。
11. 仍只通过 WPS `KET.Application` COM 修改 `.xlsx`，不依赖 Microsoft Excel。
12. 每个确认批次在写入 WPS 前按发票日期升序排列，不采用上传顺序；同一天按发票号和源文件名稳定排序。
13. 多项目、折扣/负数行和字段不确定的发票会保留已提取信息并进入 GUI 待复核，不再因明细异常而整张跳过。

多项目和折扣发票可在人工确认后写入；OCR、电子签名和订单截图匹配尚未实现。没有目录监控、开机启动或后台常驻服务。

## 安装与启动

```bat
python -m pip install -r others\requirements.txt
```

双击 `run.bat`，或执行：

```bat
python code\gui.py
```

发票 PDF 放入：

```text
C:\ClaimAgent\01-待处理
```

旧的单张命令行流程仍可用：

```bat
python code\main.py "C:\xxx\发票.pdf"
```

## 配置

在 `config.json` 中检查：

- `wps_root`：WPS 同步报销根目录
- `stats_file`：待报销统计表文件名
- `inventory_file`：入库单文件名
- `input_dir`：待处理 PDF 目录
- `completed_dir`：成功源文件归档目录
- `review_dir`：解析失败或人工待复核目录
- `backup_dir`：写入前备份目录
- `log_file`：JSONL 处理日志

当前目录映射如下：

- `C:\ClaimAgent\01-待处理`：新发票入口
- `C:\ClaimAgent\02-待复核`：解析失败或人工待复核文件
- `C:\ClaimAgent\03-已完成`：成功处理后的原始 PDF
- `C:\ClaimAgent\others\backup`：正式写入前的表格备份
- `C:\ClaimAgent\others\logs`：JSONL 处理日志
- `C:\ClaimAgent\code`：Python 程序代码
- `C:\ClaimAgent\others\tests`：自动化测试

正式 WPS 同步目录仍由根目录的 `config.json` 中 `wps_root` 单独配置。

日期排序只作用于本次确认批次中新写入的记录，不会重排 WPS 表格中已经存在的历史数据。

## 异常发票人工复核

程序启动时会同时扫描 `01-待处理` 和 `02-待复核` 中的 PDF，并避免同名文件重复加载。

可读但存在多明细、负数折扣、字段缺失或金额冲突的发票会显示为“待复核”。程序会保留已经可靠提取的发票号、日期、买卖双方、税号和发票级合计，并在 `02-待复核` 保存结构化 `.review.json`（兼容已有 `.error.json`）。

在 GUI 中可以修改发票号码、日期、买卖双方、双方税号、项目汇总、金额、类别、简称、月份、备注和材料入库字段；点击“查看/编辑发票明细”可以查看、修改、添加或删除多条明细。完成核对后勾选“我已人工核对异常字段和明细”并保存，再勾选“纳入本次批量写入”，该发票即可进入同一个最终批次确认。

多明细发票仍以票面打印的发票级不含税金额、税额和价税合计作为报销权威值。明细合计不一致时会阻止提交，不会自动覆盖票面合计。

多种正数商品的材料发票默认合并为一条入库记录，品名和简称包含全部商品，数量为 1、单位为“批”、规格为“详见发票明细”。每条商品的原始数量和单位仍保留在明细编辑窗口；单商品加折扣的发票保留该商品的数量。可按实际入库要求修改汇总字段。

解析按票面左右区域识别买卖方，按合计行的位置提取金额，兼容顺丰金额和人民币符号分开存储的 PDF。备份与正式 PDF 复制先生成临时文件并核对大小；遇到 `Invalid argument` 会尝试普通流式复制，仍失败则显示源和目标路径。备份/WPS 阶段失败也会记录异常堆栈，便于继续定位环境问题。

解析失败的 PDF 会在用户手动启动/重新扫描时移入 `02-待复核`，并生成同名 `.error.json` 原因文件。合规校验失败但能解析的发票会保留在 GUI 队列中，且默认不纳入批次，方便人工查看后再移入待复核目录。

## 首次安全测试

不要直接对唯一一份正式表格测试。

1. 复制整个个人报销目录到独立测试目录。
2. 临时把 `config.json` 的 `wps_root`、备份、完成、待复核和日志路径全部指向测试目录。
3. 准备有效单项目发票、错误抬头/税号、金额不一致和重复发票样本。
4. 先验证取消最终确认时所有正式文件完全不变。
5. 确认批次后，在 WPS 中人工检查表格格式、公式、插入行和合计。

仓库自动化测试不会连接 WPS 或正式目录：

```bat
python -B -m unittest discover -s others\tests -v
```

## 日志与重复判断

`processing.jsonl` 每行是一条 JSON 记录。成功批次包含时间、发票号、销售方、金额、类别、月份、目标 PDF、完成源文件和备份目录。解析失败与已回滚批次也会记录原因。

历史成功日志中出现相同发票号码时，系统会停止该发票所在批次并要求人工检查；不会自动覆盖目标 PDF 或完成目录中的同名文件。
